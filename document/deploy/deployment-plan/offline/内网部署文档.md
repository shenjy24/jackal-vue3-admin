# jackal-vue3-admin 内网部署文档

## 环境要求

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| Docker | ≥ 20.10 | 用于构建前端静态资源 |
| Nginx | ≥ 1.22 | 宿主机直接安装，用于反向代理和静态文件服务 |
| 操作系统 | Linux x86_64 / aarch64 | 推荐 Ubuntu 20.04+ / CentOS 7+ / Debian 11+ |

## 部署架构

```
[用户] → [宿主机 Nginx:80] → /admin/api/ → [后端服务]
                            → /* → /data/releases/current/dist/ (静态文件)
```

**核心策略**：
- Docker 仅用于构建前端（`node:24.17.0-slim` 中执行 `npm ci && npm run build`）
- Nginx 安装在宿主机上，直接读取构建产物并提供服务
- 不存在运行中的前端容器

## 版本管理

每次构建会产生一个以时间戳命名的发布目录：

```
releases/
├── 20260612_143000/
│   └── dist/              ← 构建产物（Docker build 输出）
├── 20260615_093000/
│   └── dist/
└── current -> 20260615_093000/   ← 当前使用的版本（软链接）
```

- `current` 是软链接，指向当前活跃版本
- 回滚只需重新指向旧的版本目录
- 默认保留最近 5 个版本，可在 `deploy.env` 中调整

## 部署步骤

### 1. 环境准备

安装 Docker（如已安装可跳过）：

```bash
# Ubuntu/Debian
curl -fsSL https://get.docker.com | bash
sudo usermod -aG docker $USER
# 退出重新登录后生效
```

安装 Nginx：

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install -y nginx

# CentOS/RHEL
sudo yum install -y nginx
```

### 2. 配置 Nginx

将 `document/deploy/nginx.conf` 复制到 Nginx 配置目录，**注意修改 `root` 路径**：

```bash
sudo cp /home/tech/workspace/jackal-vue3-admin/document/deploy/nginx.conf /etc/nginx/conf.d/jackal-vue3-admin.conf
```

编辑配置，将 `root` 改为当前版本目录：

```nginx
server {
    listen 80;
    server_name _;
    root /home/tech/workspace/jackal-vue3-admin/releases/current/dist;  # ← 修改此处
    index index.html;
    # ...
}
```

> **注意**：`releases/current` 始终指向最新构建版本。每次构建后如果重启 Nginx，新的 `dist/` 即可生效。

测试并重载：

```bash
sudo nginx -t
sudo nginx -s reload
```

### 3. 配置环境变量

编辑 `document/deploy/deployment-plan/offline/deploy.env`，根据实际路径修改：

```bash
PROJECT_HOME=/home/tech/workspace/jackal-vue3-admin   # 项目实际路径
NGINX_CONF_FILE=/etc/nginx/conf.d/jackal-vue3-admin.conf  # Nginx 配置路径
```

### 4. 执行构建与部署

```bash
cd /home/tech/workspace/jackal-vue3-admin
bash document/deploy/deployment-plan/offline/deploy.sh
```

脚本会自动完成：
1. Docker 构建前端（在 `node:24.17.0-slim` 中编译）
2. 输出 `dist/` 到时间戳发布目录
3. 更新 `current` 软链接
4. 重启 Nginx
5. 清理历史版本

### 5. 验证

```bash
# 查看版本目录结构
ls -la /home/tech/workspace/jackal-vue3-admin/releases/

# 查看构建产物
ls /home/tech/workspace/jackal-vue3-admin/releases/current/dist/

# 访问前端
curl -I http://localhost/

# 查看 Nginx 状态
sudo systemctl status nginx
```

## 回滚操作

### 手动选择版本回滚

```bash
cd /home/tech/workspace/jackal-vue3-admin
bash document/deploy/deployment-plan/offline/rollback.sh
```

按提示输入版本序号或版本名即可回滚。

### 命令行直接指定回滚

```bash
# 按序号（从最新版本开始编号，1 为最新）
bash document/deploy/deployment-plan/offline/rollback.sh 2

# 按版本名
bash document/deploy/deployment-plan/offline/rollback.sh 20260612_143000
```

### 手动回滚（紧急情况）

```bash
cd /home/tech/workspace/jackal-vue3-admin/releases
ln -sfn 20260612_143000 current
sudo nginx -s reload
```

## 离线镜像管理

内网环境无法直接拉取 Docker 镜像，需要先在有网络的机器上导出：

```bash
docker pull node:24.17.0-slim
docker save node:24.17.0-slim -o node-24.17.0-slim.tar
```

将 `node-24.17.0-slim.tar` 放入 `document/deploy/docker/images/images/`，然后在服务器上执行：

```bash
cd /home/tech/workspace/jackal-vue3-admin
bash document/deploy/docker/images/load-images.sh
```

之后构建脚本即可使用本地镜像。

## Nginx 配置参考

`document/deploy/nginx.conf` 内容如下：

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /admin/api/ {
        proxy_pass http://backend:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    gzip on;
    gzip_types text/plain text/css application/json application/javascript
               text/xml application/xml image/svg+xml;
}
```

部署到宿主机时需修改：
1. `root` 指向 `releases/current/dist` 的绝对路径
2. `proxy_pass` 的 `http://backend:8080/` 改为后端实际地址，例如 `http://localhost:8088/`

## 清理 Docker 构建缓存

长期持续构建会产生大量 Docker build cache，建议定期清理：

```bash
bash document/deploy/docker/cleanup/docker-cleanup.sh
```

可配置定时任务每周自动清理（参见 `docker/cleanup/Docker清理文档.md`）。

## 常见问题

### 构建失败：npm ci 报错

- 检查 `package-lock.json` 是否存在，内网环境下需同时上传源码和 `package-lock.json`
- 检查 Dockerfile 中的 npm 镜像配置是否正确

### 页面空白 / 404

- 确认 Nginx `root` 指向 `releases/current/dist`
- 确认 `releases/current` 软链接已指向预期版本
- 检查 Nginx `try_files` 配置是否包含 `$uri/ /index.html`

### 页面接口 502

- 确认后端服务地址在 Nginx 配置中正确配置
- 确认后端服务正在运行

### 回滚后未生效

- 确认 `releases/current` 软链接已更新：`ls -la releases/current`
- 确认 Nginx 已重新加载：`sudo nginx -s reload`
