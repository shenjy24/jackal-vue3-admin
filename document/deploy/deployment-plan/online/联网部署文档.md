# jackal-vue3-admin 联网部署文档

## 部署方式

online 部署采用容器化运行：

```text
git fetch/pull
  -> docker build 多阶段构建
      -> node:24.17.0-slim 编译 dist
      -> nginx:1.30.2-alpine 托管 dist
  -> docker compose up -d 启动 jackal-vue3-admin-prod
```

前端容器内部仍然运行 Nginx，但只负责静态资源和 Vue Router history fallback。生产构建通过 `VITE_APP_BASE=/admin/` 挂载到 `/admin/`，外部 Nginx 作为统一入口，负责域名、HTTPS、`/admin/` 到前端容器的转发，以及 `/admin/api/` 到后端 `service-admin` 的转发。部署流程不再维护 `releases/current` 静态目录软链接。

## 目录说明

```text
deploy/
├── app.env             # online 部署变量
├── up.sh               # 拉取代码、构建镜像、启动容器
├── down.sh             # 停止并移除前端容器
├── rollback.sh         # 从本地历史镜像回滚
├── Dockerfile          # Node 构建 + Nginx 运行镜像
├── docker-compose.yml  # 前端容器运行配置
└── nginx.conf          # 容器内静态资源 Nginx 配置
```

## 部署时目录结构

部署时服务器目录结构与 `jackal-java-server` 保持一致，`deploy` 目录与前端项目仓库目录同级：

```text
/home/tech/workspace/
├── deploy/                                    # 前端部署目录
│   ├── app.env                                # online 部署变量
│   ├── up.sh                                  # 部署脚本
│   ├── down.sh                                # 停止脚本
│   ├── rollback.sh                            # 回滚脚本
│   ├── Dockerfile                             # 前端镜像构建文件
│   ├── docker-compose.yml                     # 前端容器编排配置
│   └── nginx.conf                             # 容器内 Nginx 配置
└── jackal-vue3-admin/                         # 前端项目仓库
    ├── .env.production                        # 生产环境前端变量
    ├── package.json
    ├── package-lock.json
    ├── src/
    └── public/

/etc/nginx/
└── conf.d/
    └── jackal-vue3-admin.conf                 # 外部 Nginx 实际生效配置，可参考 document/deploy/nginx.conf

Docker
├── image: jackal-vue3-admin:prod-时间-提交号
└── container: jackal-vue3-admin-prod
```

脚本通过 `REPO_NAME` 定位前端代码仓库目录，默认路径为 `deploy/../jackal-vue3-admin`。容器化部署时，静态资源会在 Docker build 阶段生成并复制到镜像内部的 Nginx 目录；宿主机不需要维护 `dist`、`releases` 或 `current` 等发布目录。

## 前置条件

部署机需要安装：

```bash
sudo apt update
sudo apt install -y docker.io git
sudo systemctl enable --now docker
```

Docker Compose 需要使用 v2：

```bash
docker compose version
```

## 首次准备

```bash
mkdir -p /home/tech/workspace
cd /home/tech/workspace
git clone <代码仓库地址> jackal-vue3-admin
mkdir -p deploy
cp jackal-vue3-admin/document/deploy/deployment-plan/online/* deploy/
chmod +x deploy/up.sh deploy/down.sh deploy/rollback.sh
vim deploy/app.env
```

后续部署、回滚、停止都在 `/home/tech/workspace/deploy` 目录执行；`app.env` 中的 `REPO_NAME` 默认指向同级的 `jackal-vue3-admin`。

## 配置 app.env

按实际环境修改：

```bash
ENV=prod
BRANCH_NAME=main
REPO_NAME=jackal-vue3-admin
APP_PORT=18080
NODE_IMAGE=node:24.17.0-slim
NGINX_IMAGE=nginx:1.30.2-alpine
IMAGE_KEEP_COUNT=5
```

`APP_PORT` 是宿主机暴露端口，容器内固定监听 80。
`REPO_NAME` 是与 `deploy` 目录同级的前端仓库目录名。

## Nginx 配置

容器内 `nginx.conf` 只负责静态资源和 history fallback：

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

外部 Nginx 负责转发 API 和前端页面，可参考 `document/deploy/nginx.conf`：

```nginx
location /admin/api/ {
  proxy_pass http://127.0.0.1:18882/;
}

location = /admin {
  return 301 /admin/;
}

location /admin/ {
  proxy_pass http://127.0.0.1:18080/;
}
```

这会把前端请求 `/admin/api/admin/auth/loginByAccount` 转发为后端 `/admin/auth/loginByAccount`。如果 `service-admin` 或前端容器端口不同，需要同步修改外部 Nginx 配置。

## 部署

在 `deploy` 目录中执行：

```bash
cd /home/tech/workspace/deploy
bash up.sh
```

脚本会：

1. 检查 Docker、Docker Compose v2 和 Git。
2. 进入 `../jackal-vue3-admin` 前端仓库目录。
3. 拉取并快进到 `GIT_REMOTE/BRANCH_NAME`。
4. 准备临时 Docker build context，使 Dockerfile 可使用 `COPY ./nginx.conf`。
5. 使用 Docker Compose 构建镜像 `jackal-vue3-admin:prod-时间-提交号` 并启动 `jackal-vue3-admin-prod`。
6. 保留最近 `IMAGE_KEEP_COUNT` 个历史镜像并清理 dangling image。

部署完成后访问：

```text
http://服务器IP:APP_PORT/
```

## 回滚

查看并选择本地历史镜像：

```bash
bash rollback.sh
```

也可以直接指定序号或完整镜像名：

```bash
bash rollback.sh 2
bash rollback.sh jackal-vue3-admin:prod-20260624153000-abcdef1
```

回滚会复用同一个 `docker-compose.yml`，只替换 `APP_IMAGE` 并重启前端容器。

## 常用命令

查看容器：

```bash
docker ps --filter name=jackal-vue3-admin-prod
```

查看日志：

```bash
docker logs -f jackal-vue3-admin-prod
```

如果容器日志出现 `open() "/run/nginx.pid" failed (13: Permission denied)` 或 `"pid" directive is duplicate`，说明部署目录中的 `Dockerfile` 不是最新版本。请重新复制最新部署文件并重建镜像：

```bash
cd /home/tech/workspace
cp jackal-vue3-admin/document/deploy/deployment-plan/online/* deploy/
cd deploy
bash down.sh
bash up.sh
```

查看历史镜像：

```bash
docker image ls jackal-vue3-admin
```

停止服务：

```bash
cd /home/tech/workspace/deploy
bash down.sh
```

## 注意事项

- online 容器内部包含 Nginx，但不处理 `/admin/api/`。
- 宿主机外部 Nginx 需要配置 `/admin/api/` 转发到后端 admin 服务。
- `VITE_APP_BASE=/admin/` 会让构建后的静态资源自动使用 `/admin/` 前缀。
- `VITE_API_BASE_URL=/admin/api` 的生产配置保持不变，由外部 Nginx 代理到后端 admin 服务。
- 首次联网构建会拉取 `NODE_IMAGE` 和 `NGINX_IMAGE`，需要部署机能访问对应镜像仓库。
